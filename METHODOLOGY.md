# Методология — Qazaq Loc QA (кейс 02, Grand Mobile)

Как мы искали ошибки в казахской локализации, как их исправляли и сколько строк прошло через носителя языка.
Все цифры ниже получены на файлах организаторов (`intl_ru.arb`, `intl_kk.arb`, `intl_uz.arb`, `intl_en.arb`)
и воспроизводятся командами из раздела «Как воспроизвести».

## 1. Исходные данные и их особенности

| Файл | Строк | Что учли |
|---|---|---|
| `intl_ru.arb` | 5 479 | исходный язык, описания (`@key`) есть только у 9 ключей |
| `intl_kk.arb` | 5 469 | ~100 подложенных ошибок; 135 маркеров `@@comment`; 109 повторяющихся ключей, у 10 — разные переводы |
| `intl_uz.arb`, `intl_en.arb` | 5 475 / 5 480 | используются для поиска «чужого языка» в казахском файле |

Особенности формата, на которые мы опирались:

- **`@@comment` повторяется 135 раз.** Обычный JSON-парсер оставляет один. Поэтому исправленный файл собирается
  не пересохранением JSON, а точечной правкой исходного текста: порядок ключей, все `@@comment`, пустые строки,
  отступы и Unix-переводы строк сохраняются байт в байт, меняются только исправленные строки.
- **Плейсхолдеры** — `{name}`, `{count}` и `%s`. ICU-плюралов в файлах нет, но инструмент их разбирает
  (`plural`/`select`, обязательная форма `other`, баланс скобок) — это проверено тестами.
- **`currencySymbol`** содержит символ из private-use области шрифта — строки без букв не считаются ошибкой.
- **Повторяющиеся ключи** с разными значениями отмечаются как `inconsistent_term`: Flutter берёт последнее.
- **Пустые фрагменты составных фраз** (`…Prefix`, `…Suffix`, `…Title1`) в казахском часто пусты намеренно —
  другой порядок слов. Такие строки не отмечаются.
- **Совпадение с русским** легитимно для брендов, имён, чисел и заимствований — см. п. 2.2.

## 2. Как искали ошибки — три слоя

### 2.1. Детерминированные правила (`locqa check`)

Строки сравниваются с русским оригиналом по ключу. 11 проверок — по таксономии кейса:

| Тип | Как ищем |
|---|---|
| `untranslated` | ключа нет или перевод пустой (кроме фрагментов составных фраз) |
| `same_as_source` | текст совпадает с русским; пропускаем цифры, латиницу, одиночные заимствования и слова из глоссария с `keep=yes` |
| `placeholder_mismatch` | наборы `{…}` и `%s` различаются; подсказываем, если потеряны скобки или опечатка в имени (`{leve}`) |
| `plural_mismatch` | разбор ICU `plural/select`: форма `other`, наличие конструкции, баланс скобок |
| `glossary_violation` | обязательный термин (`enforce`) отсутствует или использован запрещённый вариант (`kk_wrong`) |
| `length_overflow` | короткий элемент стал в 3+ раза длиннее, кнопка — в 1,8+ раза; ловим «хвосты» («…үшін басыңыз», «режимін қосу және жалғастыру») |
| `machine_translation_suspect` | русские служебные слова и окончания в казахском тексте, кальки («болып табылады», «Бұл - … бар …») |
| `inconsistent_term` | ключ объявлен несколько раз с разными переводами |
| `suffix_harmony` | падежный аффикс сразу после плейсхолдера (`{name}-ға`) + автоматическая переформулировка без аффикса |
| `orthography` | смешение кириллицы и латиницы в слове (`бөлімiне`); русская буква вместо казахской — сравниваем частоту написаний в файле («колжетімді» ×1 против «қолжетімді» ×78) |
| `wrong_language` | строка совпадает с узбекским/английским файлом, латиница в кириллической локали, узбекские буквы ў/ҳ |

Результат: **117 находок** без глоссария, **149** с глоссарием.

### 2.2. Глоссарий (`glossary.csv`, 97 терминов)

Колонки: `ru`, `kk`, `en`, `uz`, `comment`, `kk_wrong`, `enforce`, `keep`.

- Пять терминов из задания (фракция, семья, Grand Coins, бизнес, варн) — обязательные (`enforce=yes`).
- 18 терминов с запрещёнными вариантами, найденными в файле: «отмена» ≠ «бастау» (старт), «ставка» ≠ «тігіс» (шов),
  «баланс» ≠ «қолма-қол» (наличные), «фары» ≠ «бағдаршам» (светофор), «трансмиссия» ≠ «тарату» и др.
- Сленг игроков учтён: «варн», «мут», «фура», «ГК», «ивент», «донат» — допустимые варианты, а не ошибки.
- 11 терминов «не переводится» (`keep=yes`): названия механик, имена персонажей, топонимы, тех-термины.

### 2.3. Смысловая вычитка с LLM

Правила не видят ошибок смысла вида «Баланс → қолма-қол ақша (наличные)». Поэтому все **3 652 короткие строки**
(≤ 25 символов исходника), не пойманные правилами, вычитаны языковой моделью (LLM) в рабочей сессии.
Дополнительно сверили результат с веб-инструментом участника команды (`web/`): это дало блок из 12 строк ивента
Twix, переведённых текстом другого ивента. Всего **116 смысловых находок**, они лежат в
`reports/llm_findings_kk.json` и добавляются в отчёт флагом `--include`. Платный API не использовался.

Для автоматического прогона на новых файлах есть `locqa check --llm` (LLM через API, пачки по 40 строк);
стоимость считается по фактическим токенам и сохраняется в `*.llm_cost.json`.

**Итог по intl_kk.arb: 265 находок** — high 180, medium 83, low 2:

| Тип | Находок | Тип | Находок |
|---|---|---|---|
| machine_translation_suspect | 118 | same_as_source | 13 |
| glossary_violation | 43 | placeholder_mismatch | 12 |
| orthography | 19 | untranslated | 12 |
| wrong_language | 17 | inconsistent_term | 10 |
| length_overflow | 13 | suffix_harmony | 8 |

У каждой находки — `evidence` (почему это ошибка, с цифрами), `severity`, `confidence` и, где возможно, `suggestion`.

## 3. Как исправляли

1. **Предложения.** Для каждой находки подготовлен вариант исправления: из правила (вернуть скобки плейсхолдера,
   заменить русскую букву на казахскую, убрать «хвост»), из глоссария или из смысловой вычитки.
   Массово «перевести заново» мы сознательно не стали — меняются только строки с найденной проблемой.
2. **Проверка носителем.** Таблица `reports/review_kk.csv` открывается на странице `reports/proverka_kk.html`:
   оригинал, текущий перевод, предложение, причина. Носитель принимает, правит или оставляет строку как есть.
   Страница не даёт сохранить правку со сломанным плейсхолдером или скобкой.
3. **Сборка.** `locqa apply` берёт только строки, где заполнен `reviewer`, и пишет в метаданные:
   ```json
   "@key": {"x-reviewed_by_human": true, "x-reviewer": "Жансая", "x-original": "старый текст"}
   ```
4. **Проверка сборки.** `locqa validate` повторяет проверки `flutter gen-l10n`: валидный JSON, ICU-синтаксис,
   плейсхолдеры, которых нет в шаблоне. Исходный `intl_kk.arb` **не проходит** (2 ошибки: `{platformColo}`, `{leve}` —
   сборка игры упала бы), `intl_kk_fixed.arb` — проходит.

## 4. Сколько строк прошло через носителя

Проверку выполнила носитель казахского языка **Жансая**.

| | Строк |
|---|---|
| Строк в таблице проверки | **330** |
| Просмотрено носителем | **330** (100%) |
| Принято или исправлено | 272 (из них 3 носитель переписала сама) |
| Оставлено как было в игре | 58 (в т.ч. 8 наших предложений отклонено, например термины тюнинга «развал») |

## 5. Точность (precision)

**Версия 1** (289 находок): 50 случайных находок разметил носитель — верных **45 / 50 = 90%**
(`reports/precision_sample_kk_v1_native.csv`). Ложными оказались три класса:

| Класс ложных срабатываний | Что изменили |
|---|---|
| пустые фрагменты составных фраз | больше не отмечаются |
| «осталось по-русски» на названиях и терминах («Минус Вайб», «ЧИП-ТЮНИНГ») | колонка `keep` в глоссарии |
| «слишком длинно» на верном, но длинном переводе | порог поднят до ×3; смысловые ошибки, ловившиеся длиной, перенесены в `machine_translation_suspect` |

**Версия 2** (265 находок): новая случайная выборка из 50 (seed 2027, `reports/precision_sample_kk.csv`):
**49 / 50 = 98%** по предварительной разметке; единственное спорное — название ивента «SUMMER RUSH» латиницей.
Финальную разметку этой выборки делает носитель.

## 6. Бонусы

- **Узбекский.** Тот же инструмент без правок: `report_uz.json` — 41 находка (кириллические буквы и аффиксы в
  латинском тексте: «Arenaга», «Mashинаni»; потерянный `%s`; непереведённые строки). Таблица `review_uz.csv` и
  страница `proverka_uz.html` готовы; проверка носителем узбекского не проводилась, поэтому `intl_uz_fixed.arb`
  остаётся черновиком (`reports/intl_uz_fixed_DRAFT.arb`, все правки `x-reviewed_by_human: false`).
- **Транслитерация в латиницу** (`locqa translit`): казахский алфавит на латинице, версия 2021 г.
  (Ә→Ä, Ғ→Ğ, Қ→Q, Ң→Ñ, Ө→Ö, Ұ→Ū, Ү→Ü, Ш→Ş, Ч→Ç, І→I/ı, Ы→Y, И/Й→İ/i); плейсхолдеры и теги не трогаются.
  Проверка длины: 22 строки на латинице заметно длиннее кириллицы (из-за «ц→ts», «я→ia»: «ФРАКЦИЯ → FRAKTSİIA»).
- **GitHub Action** (`.github/workflows/locqa.yml`): тесты, демо на синтетическом примере и проверка ARB
  на каждый pull request с изменением `.arb`.
- **Переформулировка аффиксов:** у находок `suffix_harmony` есть `suggestion` без аффикса после плейсхолдера
  («{price}-ге сатып алу» → «Сатып алу: {price}»).

## 7. Универсальность

- Работает с любым ARB без правок кода: локаль берётся из `@@locale` или имени файла, письменность — автоматически;
  казахские проверки включаются только для `kk`.
- `examples/` — синтетический пример из 18 строк (не данные игры), в котором инструмент находит все 11 типов ошибок.
- 26 автотестов, зависимостей нет (только Python 3.9+).

## 8. Ограничения

- `same_as_source` остаётся самым слабым правилом на коротких заимствованиях — нужен пополняемый список `keep`.
- Смысловая вычитка покрыла строки до 25 символов; длинные тексты проверены только правилами.
- Транслитерация сделана по алфавиту 2021 г.; при изменении стандарта таблицу букв нужно обновить.
- `validate` повторяет основные проверки `flutter gen-l10n`, но не заменяет его: перед релизом файл нужно один раз
  собрать настоящим Flutter.

## 9. Как воспроизвести

```bash
# 1. Поиск ошибок (правила + глоссарий + смысловые находки)
./locqa check --source data/intl_ru.arb --target data/intl_kk.arb --glossary glossary.csv \
    --include reports/llm_findings_kk.json --out reports/report_kk.json

# 2. Сборка исправленного файла из проверенной таблицы
./locqa apply --target data/intl_kk.arb --review reports/review_kk.csv \
    --out intl_kk_fixed.arb --report reports/report_kk.json

# 3. Проверка совместимости с Flutter
./locqa validate intl_kk_fixed.arb --template data/intl_ru.arb

# Бонусы
./locqa check --source data/intl_ru.arb --target data/intl_uz.arb --glossary glossary.csv --out reports/report_uz.json
./locqa translit --source data/intl_ru.arb --target intl_kk_fixed.arb --out reports/intl_kk_latn.arb
```

Для поиска «чужого языка» положите `intl_uz.arb` и `intl_en.arb` в ту же папку, что и проверяемый файл:
инструмент сравнит строки с ними автоматически.
